# G03 transport correction — 2026-11-06

Scope: private synthetic files. G05 remains open. No Fortnox operation,
production-support claim, merge or release.

## Invalid native Worker assumption

The former adapter connected to a validated public IP and supplied the URL
host through `startTls({ expectedServerHostname })`. The fake-socket test
checked the argument, not certificate validation on the public edge.
Cloudflare's [socket implementation](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/sockets.c%2B%2B)
marks this option unsupported, with an autogate that can reject it. The primary
reproducer in [workerd #6903](https://github.com/cloudflare/workerd/issues/6903)
reports ignored SNI and silent EOF on the edge while local workerd works.
Our failure before response headers is consistent with that report; we did not
capture the edge ClientHello. The unsupported assumption is sufficient to
retire this native adapter. A local test is not a wire-level TLS guarantee.

The workerd/D1 fixture now also runs fragmented socket HTTP through parsing,
validation, encryption and storage. It passes, but does not establish the
public platform's TLS behavior. The Worker no longer imports the native adapter.

## Explicit temporary Node relay

The Worker returns `FILE_TRANSPORT_UNAVAILABLE` unless the operator explicitly
selects `PROBE_FILE_TRANSPORT=node-relay` and configures the separate helper URL,
token and deadline. There is no automatic unpinned `fetch` fallback.

The helper uses the existing Node HTTPS transport: all resolved addresses must
be public; socket lookup is pinned to an already checked address; TLS explicitly
verifies the original URL host. Incoming cookies/authorization are not forwarded
to the file host, and redirects are not followed.

The helper has eight attempts, a session of at most 15 minutes, exact reviewed
source origins, 8 KiB JSON input and the Worker 1 MiB file limit. It rejects
browser Origin headers, missing/wrong credentials, extra fields, query strings
and expired sessions, including a second deadline check after download. It has
no arbitrary-header, filesystem, company or financial interface. Bodies exist
only in memory. MCP owner/scope checks, validation, encryption, owner/company
binding, 55-minute references and D1 cleanup remain on the Worker.

Only a temporary `trycloudflare.com` HTTPS helper origin is accepted in this
slice. The token is independent of owner/OAuth/runtime secrets. Signed source
URLs and request bodies are not logged. This is an explicit development route,
not a permanent service or proof of native Worker egress.

## Operator procedure

1. Verify owning Worker/account, bindings, staged state and cleanup cron; keep
   file ingress off during preparation.
2. Create ignored `.data/file-relay.json` with a random 64-hex `token`, exact
   `origins` and UTC `until` no more than 15 minutes ahead. Store the same token
   in the new `PROBE_FILE_RELAY_TOKEN` Worker secret. Never print the token.
3. Run `node --import tsx scripts/serve-file-relay.ts`. It binds loopback:8796
   and closes its listener at expiry. Expose only this service through an
   official temporary Cloudflare Tunnel.
4. Set exact `PROBE_FILE_RELAY_ORIGIN`, `PROBE_FILE_RELAY_UNTIL` and explicit
   transport mode. Enable synthetic files only with reviewed source origins
   and the cleanup assertion. Do not widen existing OAuth grants.
5. In Chrome upload known synthetic fixtures; compare server hashes/lengths,
   retrieve outputs and distinguish relay evidence from native Worker support.
6. Disable ingress/diagnostics, empty source origins, remove helper settings
   and secret, stop tunnel/helper, clear only this test's staged workflow and
   verify file/chunk counts. Preserve scheduled cleanup.
