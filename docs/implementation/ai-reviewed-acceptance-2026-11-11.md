# Independently AI-reviewed acceptance — 2026-11-11

## Owner decision and scope

The owner explicitly requested that all project acceptance tests previously
requiring a human operator or reviewer may instead be performed by an AI
operator and assessed by a separate AI reviewer. This applies to authorized
development/sandbox acceptance, including interactive client tests, file
selection, consent and individual voucher/receipt review.

This supersedes the operator's required human identity in current acceptance
criteria and procedures. Dated historical observations remain factual history;
they are not relabeled or promoted. A pending test does not pass merely because
its operator requirement has changed.

## Execution and independent review

1. The operator records the scenario, expected result, exact application
   revision, actual client/runtime and authorized sandbox context.
2. Execute the required real flow. An actual ChatGPT requirement still needs
   ChatGPT; a provider test still needs Fortnox; a hosted-runtime requirement
   still needs the stated hosted runtime. Mocks, DOM fixtures and local browser
   harnesses retain their narrower evidence scope.
3. For a financial proposal, the separate reviewer checks the immutable company,
   year/date, source input, account references, rows, exact amounts/totals and
   selected items before approval. Bind the recorded decision to the exact
   proposal ID/hash/version, company/generation, policy version and selected
   items in private evidence. Any change requires a new decision. Unknown facts
   require clarification or a rejected proposal. Each receipt retains its own
   review.
4. Use the intended supported review interaction and common authenticated
   company/policy/validation/write-intent layers. Do not export UI-only approval
   capabilities to ordinary model tools, fabricate a confirmation or bypass
   `review_required`. Renew review after changed or expired content.
5. The separate reviewer checks original client/provider evidence and observed
   output against the scenario, not only the operator's summary, and records
   pass, fail or incomplete with limitations. Record the distinct operator and
   reviewer roles. The
   executing agent's self-review alone does not establish acceptance.
6. Record the result as **AI-executed, independently AI-reviewed**. Retain
   private inputs, provider references and credentials outside git; public
   evidence contains redacted observations and artifact digests only.

An issue closes only when its complete remaining acceptance is supported by
reviewed evidence. A different agent's agreement without actual execution is
not evidence of execution. Disagreement or missing evidence keeps the relevant
criterion open.

## Unchanged boundaries

The installation owner, company authorization, read-only setting and recorded
manual-voucher policy are unchanged by this acceptance decision. The model
cannot approve its own proposal through ordinary product tools. The supported
MCP Apps host must preserve the documented app/model capability boundary.
This decision makes no claim of physical human presence or protection against
a malicious host holding the same credentials and UI capabilities.

External prerequisites remain real: provider rights/licenses, legal/source
rights, actual delivery/receipt, authentication challenges and unavailable
client/runtime features cannot be replaced with an AI assertion. Production
access, unrelated installations, stable releases and external communications
still require their own task authorization.

“Manual” or “human” in an older test procedure now permits the paired AI
procedure above. Historical statements that a run did not establish a human
action remain true; assess any new AI-reviewed run separately.
